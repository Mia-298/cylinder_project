# 手眼标定精度验证软件包技术报告

## 1. 文档目的

本文档说明 `gas_handeye_validation` 软件包的整体设计、验证逻辑、输入输出、模块架构、指标含义和实际操作流程。

这个软件包的目标不是重新做手眼标定，而是验证一个已经存在的手眼标定结果到底稳定不稳定、精度大概是多少。

在当前项目中，被验证的手眼结果通常是：

```text
calibration_data/handeye/20260811_225315/results/handeye_result.yaml
```

该结果来自 2026-08-11 采集的手眼标定数据。

## 2. 背景说明

手眼标定的核心目的是求出相机和机器人末端工具之间的固定关系。

在本项目中，这个关系记为：

```text
T_tool_camera
```

它表示相机坐标系和机器人末端工具坐标系之间的空间变换关系。

有了这个变换后，视觉系统看到的目标、标定板或特征点，就可以被转换到机器人坐标系下，用于抓取、定位和误差分析。

但标定完成后，不能只看一个矩阵。还要回答一个实际问题：

```text
这个手眼矩阵在不同机器人姿态、不同观察角度下是否稳定？
```

`gas_handeye_validation` 就是为回答这个问题而写的验证软件包。

## 4. 功能介绍

`gas_handeye_validation` 提供以下功能：

1. 读取已有手眼标定结果 `handeye_result.yaml`
2. 固定其中的 `T_tool_camera`
3. 通过 GUI 显示相机画面和 Charuco 角点检测结果
4. 支持机器人拖动模式开启 / 退出
5. 在不同角度下重新采集验证样本
6. 每次采样时读取机器人当前 TCP 位姿 `T_base_tool`
7. 每次采样时根据图像重新求标定板在相机下的位姿 `T_camera_board`
8. 使用固定的手眼矩阵计算每个样本的 `T_base_board`
9. 统计所有 `T_base_board` 的平移散布和旋转散布
10. 输出 YAML、CSV 和 Markdown 格式的验证报告

## 5. 一句话理解验证逻辑

标定板在验证过程中必须固定不动。

如果手眼标定准确，那么机器人从不同角度看到同一块固定标定板时，经过下面的计算：

```text
T_base_board_i = T_base_tool_i * T_tool_camera * T_camera_board_i
```

每个样本算出来的 `T_base_board_i` 应该几乎一样。

如果它们彼此差很多，说明这套手眼标定结果在实际空间中不稳定。

## 6. 坐标系说明

本模块涉及 4 个主要坐标系：

| 坐标系 | 含义 |
| --- | --- |
| `board` | 标定板坐标系，Charuco 角点的 3D 坐标定义在这里 |
| `camera` | 相机坐标系，相机看到的 3D 点都先落在这里 |
| `tool` | 机器人末端工具坐标系 |
| `base` | 机器人基坐标系 |

核心变换如下：

| 变换 | 来源 | 含义 |
| --- | --- | --- |
| `T_camera_board` | 图像检测 + PnP 求解 | 标定板在相机坐标系下的位置和姿态 |
| `T_base_tool` | 机器人控制节点 `/robot/get_pose` | 机器人末端在基坐标系下的位置和姿态 |
| `T_tool_camera` | 已有手眼标定结果 | 相机和机器人末端工具之间的固定关系 |
| `T_base_board` | 本验证包计算 | 标定板在机器人基坐标系下的位置和姿态 |

## 10. 原理说明

### 10.1 一张图如何得到 `T_camera_board`

标定板自身坐标系中，每个 Charuco 角点的 3D 坐标是已知的：

```text
P_board = (X, Y, 0)
```

相机图像中，可以检测到这些角点的 2D 像素坐标：

```text
p_image = (u, v)
```

相机内参 `K` 和畸变参数 `D` 来自：

```text
/camera/color/camera_info
```

程序用 `solvePnP()` 求解：

```text
T_camera_board = [R | t]
```

通俗解释：

```text
已知板子上点的真实几何位置，
也知道它们在照片里出现在哪里，
再结合相机镜头参数，
反推这块板子相对于相机到底摆在哪里、转了多少角度。
```

### 10.2 重投影误差如何计算

求出 `T_camera_board` 后，程序把标定板上的 3D 角点重新投影回图像：

```text
board 3D 点 -> T_camera_board -> camera 3D 点 -> K,D -> image 2D 点
```

然后比较：

```text
投影出来的 2D 点
vs
图像中真实检测到的 2D 点
```

两者的像素差做 RMS 统计，就是：

```text
reprojection_error_px
```

它只表示图像层面的拟合质量，不直接代表机器人空间中的毫米级误差。

### 10.3 如何验证手眼矩阵

已有手眼结果提供：

```text
T_tool_camera
```

每次验证采样时，机器人控制节点提供：

```text
T_base_tool_i
```

图像检测提供：

```text
T_camera_board_i
```

程序计算：

```text
T_base_board_i = T_base_tool_i * T_tool_camera * T_camera_board_i
```

如果标定板固定不动，理论上每个 `T_base_board_i` 都应该相同。

实际中由于角点检测误差、相机内参误差、机器人位姿误差、手眼矩阵误差等原因，它们不会完全相同。

因此程序统计这些 `T_base_board_i` 的散布程度，作为手眼标定精度验证结果。

## 11. 指标说明

### 11.1 `reprojection_error_px`

含义：

```text
图像检测点和重投影点之间的像素 RMS 误差
```

单位：

```text
px
```

它反映：

```text
单张图里标定板角点和板子位姿拟合得好不好
```

数值越小越好。

### 11.2 `reprojection_rms_px`

含义：

```text
本次所有验证样本的重投影误差 RMS
```

它反映：

```text
本次验证过程中图像检测整体质量
```

### 11.3 `validation_translation_rms_mm`

含义：

```text
所有验证样本计算出来的 T_base_board 位置相对于平均板位姿的 RMS 散布
```

单位：

```text
mm
```

它反映：

```text
固定手眼矩阵后，不同观察角度下反算出的标定板位置是否一致
```

这是本验证包最重要的空间位置指标。

### 11.4 `validation_rotation_rms_deg`

含义：

```text
所有验证样本计算出来的 T_base_board 朝向相对于平均板位姿的 RMS 散布
```

单位：

```text
deg
```

它反映：

```text
固定手眼矩阵后，不同观察角度下反算出的标定板方向是否一致
```

### 11.5 `charuco_count`

含义：

```text
当前图像中成功检测并用于求位姿的 Charuco 角点数量
```

角点越多，通常 `T_camera_board` 越稳定。

本模块默认要求：

```text
min_charuco_corners = 12
```

少于 12 个角点时，GUI 会拒绝采样。

```text

```

功能：

- 固定使用已有 `T_tool_camera`
- 不重新标定
- 仅验证该手眼结果是否稳定

## 15. 实际运行步骤

### 15.1 构建软件包

```bash
source /opt/ros/humble/setup.bash
colcon build --packages-select gas_handeye_validation
source install/setup.bash
```

### 15.2 启动 2026-08-11 手眼结果验证

```bash
source install/setup.bash
ros2 launch gas_handeye_validation handeye_validation.launch.py \
handeye_result_file:=calibration_data/handeye/20260811_225315/results/handeye_result.yaml
```

### 15.3 如果相机和机器人已经启动

可以只启动验证 GUI：

```bash
ros2 launch gas_handeye_validation handeye_validation.launch.py \
use_camera:=false \
use_robot:=false \
handeye_result_file:=calibration_data/handeye/20260811_225315/results/handeye_result.yaml
```

### 15.4 GUI 操作流程

1. 启动后确认右侧 `handeye` 路径是否为要验证的 `handeye_result.yaml`
2. 确认相机画面正常显示
3. 确认标定板角点能被检测到
4. 点击 `拖动开启`
5. 移动机器人到第一个验证角度
6. 在 `姿态标签` 中选择或输入当前角度，例如 `front`
7. 点击 `采集验证样本`
8. 换下一个角度，例如 `left_yaw`
9. 重复采样，建议至少 8 组
10. 点击 `生成报告`
11. 在 GUI 右侧查看报告路径

## 16. 建议验证姿态

标定板必须固定不动，只移动机器人末端或相机观察角度。

建议姿态：

| 标签 | 说明 |
| --- | --- |
| `front` | 正视标定板 |
| `left_yaw` | 向左偏航观察 |
| `right_yaw` | 向右偏航观察 |
| `pitch_up` | 上俯仰观察 |
| `pitch_down` | 下俯仰观察 |
| `roll_left` | 左滚转观察 |
| `roll_right` | 右滚转观察 |
| `near` | 近距离观察 |
| `far` | 远距离观察 |

不要只在很小范围内轻微移动。姿态变化太小，不能充分验证手眼矩阵在不同角度下的稳定性。

```text
  ├── 检查误差最大的样本
  └── 打开 debug 图确认角点质量
```

## 18. 如何解读结果

### 18.1 重投影 RMS 很小，但平移 RMS 很大

说明图像角点检测本身不错，但空间链路有问题。

可能原因：

- 手眼矩阵不准
- 机器人 TCP 设置不准
- 机器人位姿读取有误
- 标定板在验证过程中移动了
- 采样时机器人没有稳定下来
- 相机内参或畸变参数不准

### 18.2 角点数量太少

说明当前图像对 `T_camera_board` 的约束不够。

建议：

- 调整角度，让标定板更多区域进入画面
- 避免过度倾斜
- 避免模糊
- 避免反光

### 18.3 某一个样本误差特别大

应优先查看：

```text
debug/sample_XXXX_debug.png
samples/sample_XXXX.yaml
```

判断是否是单张图像检测失败、角点太少、机器人未稳定、姿态记录异常。

## 19. 与原手眼标定包的区别

| 软件包 | 作用 |
| --- | --- |
| `gas_handeye_calibration` | 采集样本并求解新的手眼矩阵 |
| `gas_handeye_validation` | 固定已有手眼矩阵，重新采样验证精度 |

简单理解：

```text
calibration = 求矩阵
validation = 验证矩阵
```

## 20. 注意事项

1. 验证过程中标定板必须固定。
2. 每次采样前机器人应稳定，不要还在晃动时点击采集。
3. 每个样本角点数量越多越好。
4. 验证姿态要覆盖不同方向，不要集中在一个小范围。
5. 生成报告后，应重点看平移 RMS 和旋转 RMS。
6. `reprojection_error_px` 不是毫米误差，它只表示图像像素层面的拟合质量。
7. `validation_translation_rms_mm` 才是空间位置一致性的核心验证指标。
8. `validation_rotation_rms_deg` 是空间方向一致性的核心验证指标。

## 21. 本模块最终能回答的问题

运行完整验证流程后，本模块可以回答：

```text
1. 当前手眼结果在不同观察角度下是否稳定？
2. 固定手眼矩阵后，反算出的标定板位置散布是多少毫米？
3. 固定手眼矩阵后，反算出的标定板方向散布是多少度？
4. 哪些样本误差最大？
5. 误差大是图像检测问题，还是空间链路问题？
```

## 22. 推荐汇报表述

完成验证后，可以按下面格式汇报：

```text
使用 gas_handeye_validation 对指定 handeye_result.yaml 进行了独立验证。
验证过程中标定板保持固定，机器人从多个不同姿态观察标定板。
每个样本分别计算 T_camera_board、读取 T_base_tool，
并使用固定 T_tool_camera 反算 T_base_board。

最终以所有 T_base_board 的空间散布作为手眼标定验证精度：
平移 RMS 为 XX mm，旋转 RMS 为 XX deg，
图像重投影 RMS 为 XX px。
```
